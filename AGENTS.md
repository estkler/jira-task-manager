# Работа над Jira Tasklet

Пользователь уже передал приложение коллеге для тестирования. Публичные сборки используются на других компьютерах.

## Журнал изменений

- При каждом пользовательском изменении добавляй краткую запись на русском в раздел «Не выпущено» файла `CHANGELOG.md`.
- Записывай результат для пользователя: что добавилось, изменилось или исправлено. Не включай личные данные, токены, диагностические логи и историю обсуждения.
- Перед публикацией переноси накопленные записи в раздел с номером версии и датой публикации. Не удаляй историю предыдущих версий.
- Описание GitHub Release составляй по тому же разделу журнала. Если релизы пропускали локальные промежуточные версии, укажи это явно.
- Дополнения к инструкции в архиве также отражай в журнале. Не подменяй уже выпущенный EXE другим кодом под прежним номером версии.

## Публикация

- Для изменений программы используй новый номер версии. Сверяй номер в коде, ресурсах EXE, manifest, README, теге и релизе.
- Сначала проверяй изменения и собирай EXE, затем публикуй исходники, тег и файлы из одной проверенной сборки.
- Сохраняй совместимое имя release asset `Jira.Task.Manager.exe`: оно используется встроенным обновлятором.
- Проверяй GitHub latest release, распознавание версии обновлятором, размер и SHA-256 опубликованного EXE.
- Переносимый архив для коллеги должен содержать только готовый EXE и общую инструкцию. Не добавляй настройки, аккаунт, учётные данные, кэш, заметки или логи рабочего компьютера.
- Для исправления только README допускается замена ZIP той же версии с записью об этом в истории; EXE при этом должен сохранить контрольную сумму.
- Не публикуй внутренние превью, рабочие планы и диагностические материалы вместе с продуктом.

## Локальная работа

- Не добавляй новые библиотеки без необходимости и явного согласования: приложение должно оставаться лёгким.
- При локальном обновлении сохраняй начало текущего рабочего дня, настройки и локальные данные. Открытые черновики не должны теряться.
- Различай «реализовано», «проверено», «установлено локально» и «опубликовано на GitHub». В отчёте называй фактический статус.
