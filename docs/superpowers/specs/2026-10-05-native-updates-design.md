# Обновления Jira Task Manager через GitHub Releases

Статус: описание подготовлено для согласования; механизм ещё не реализован.

## Что увидит пользователь

В «Настройки → О приложении» появится кнопка «Проверить обновления».
Проверка не блокирует интерфейс. Если есть новая стабильная версия, приложение
показывает номер версии и предлагает скачать и установить её. Ничего не
устанавливается автоматически без подтверждения.

После установки приложение перезапускается. Настройки, заметки, шаблон
комментария, язык, тема, таймер и автозапуск сохраняются. Перед заменой EXE
создаётся резервная копия. Незавершённая работа не теряется: установка недоступна,
пока есть выполняющийся запрос Jira, несохранённая заметка, непустой черновик Jira
комментария или открытое окно завершения задачи.

## Цель и границы

- Канал: публичный `estkler/jira-task-manager`, только стабильные GitHub Releases.
- Приложение остаётся нативным Win32; никаких дополнительных библиотек,
  устанавливаемых сервисов, фоновых планировщиков или обязательного GitHub-входа.
- Проверка запускается вручную; в первом выпуске нет фоновых автопроверок.
- Обновляется только EXE приложения в его текущей папке. Не переименовываются
  пользовательское хранилище, ключ Windows Credential Manager и данные таймера.
- Работа в папке без права записи заканчивается понятной ошибкой; автоматического
  повышения прав, изменений защиты Windows и обхода предупреждений нет.
- Не меняем Jira-функции, логотип, переключатель режимов и дизайн списка задач.

## Выбор подхода

1. **Рекомендуемый:** нативная проверка и установка после подтверждения. Удобный
   пользовательский сценарий; нужен безопасный отдельный режим замены EXE.
2. Проверка версии и открытие страницы Releases в браузере. Проще, но установка
   остаётся ручной и не выполняет выбранный сценарий «скачать и установить».
3. Отдельный установщик/служба обновлений. Для одного EXE избыточно; не входит
   в этот этап и добавляет установочные зависимости.

## Компоненты и поток

### Проверка и скачивание

Отдельный `native_update` модуль работает через Windows WinHTTP и существующий
JSON-парсер. Основной поток окна получает только результаты и прогресс.

Проверка читает `/repos/estkler/jira-task-manager/releases/latest` без токена Jira
и без GitHub-учётных данных. Разбираются tag, draft/prerelease, ID и метаданные
единственного подходящего x64 EXE-asset `Jira.Task.Manager.exe`.
Версия имеет формат `vMAJOR.MINOR.PATCH` или `MAJOR.MINOR.PATCH`; части сравниваются
численно. Некорректные версии, черновики, предварительные выпуски, несколько
совпадающих файлов и неподходящая архитектура не предлагаются к установке.

Нужны корректные размер и `digest` вида `sha256:` плюс 64 hex-символа. Если digest
не предоставлен, автоматическая установка запрещена. Размер EXE ограничен 16 MiB,
ответа JSON — 1 MiB. Сетевые операции имеют конечные таймауты и поддерживают отмену.

Скачивание начинается с GitHub API asset ID выбранного релиза; произвольный URL
из текста релиза не исполняется и не открывается. Только HTTPS, обычная проверка
сертификатов, конечное число перенаправлений и проверка каждого перехода. Разрешены
`api.github.com`, `github.com`, `release-assets.githubusercontent.com` и
`objects.githubusercontent.com`; иные хосты и переходы на HTTP отвергаются.

Файл записывается в новый приватный временный каталог. Проверяются размер,
SHA-256, PE/архитектура и версия. Изменённый, неполный, чужой либо более старый
файл не запускается. SHA-256 проверяет соответствие файлу, опубликованному в этом
GitHub-репозитории; это не независимая цифровая подпись автора. Доверие к каналу
основано на HTTPS и контроле владельца над аккаунтом и репозиторием.

### Установка и восстановление

Проверенный EXE запускается как помощник с отдельным режимом `--apply-update`.
Это тот же нативный файл, а не скачанный скрипт. Параметры запуска формируются
через Windows API с корректной обработкой пробелов; нет cmd/PowerShell-команд,
интерпретации release notes и команд из сети.

Помощник проверяет текущий процесс приложения, точный целевой путь, версию и
источник временного файла, ждёт штатного завершения родителя с конечным таймаутом.
Запуск режима помощника не активирует обычный singleton и не подключается к Jira.

Перед завершением основное приложение сохраняет состояние и проверяет отсутствие
несохранённой работы во всех прикреплённых и отсоединённых панелях. После закрытия
помощник создаёт резервную копию старого EXE, выполняет замену в той же папке и
перезапускает новый EXE. При ошибке замены восстанавливает старый файл и сообщает
причину; настройки не изменяются. После успешного запуска нового процесса
сохраняются резервная копия и запись результата обновления для диагностики.
Не объявляем гарантированное восстановление при полном отказе диска/ОС.

### Окно настроек и жизненный цикл

В существующем блоке «Обновления» меняются сообщение и добавляется кнопка
проверки; отдельная вкладка не появляется. Состояния: проверка, текущая версия,
новая версия, скачивание, установка/перезапуск и ошибка с повтором.

Закрытие настроек безопасно отменяет или отсоединяет проверку: сообщения не
обращаются к уничтоженным HWND, а повторное открытие не получает результаты
устаревшего запроса. Язык и тема сохраняют обычное поведение приложения.
В логах нет токенов, комментариев, Jira URL или текста заметок.

## Публикация

Первый клиент с обновлением получает новую версию после 0.9.29. Для каждого
стабильного релиза tag соответствует версии в исходниках и ресурсах EXE.
GitHub Release содержит проверенный EXE с постоянным asset-name
`Jira.Task.Manager.exe`; пользовательские настройки и диагностика не публикуются.
Предыдущие релизы и assets не удаляются. В этом этапе публикация ручная;
автоматическая сборка/публикация в Actions — отдельная последующая задача.

## Проверка готовности

- Тесты разбора версий и релизов, отсутствия релиза/asset/digest, malformed JSON,
  слишком больших ответов, неправильных хостов, HTTP-переходов и превышения числа
  перенаправлений. Fixture transport без реальных сетевых записей.
- Тесты SHA-256/размера/PE/версии на корректном и повреждённом тестовом EXE.
- Интеграционный тест помощника в изолированной временной папке: ожидание
  родителя, пробелы в путях, блокировка файла, таймаут, успешная замена, резервная
  копия и восстановление при ошибке. Не обновляем реальную установку в этих тестах.
- Тесты запрета установки при Jira job и черновиках, сохранения таймера и данных,
  закрытия настроек и игнорирования устаревших результатов.
- Полный существующий набор тестов и сборка, визуальная проверка RU/EN и обеих
  тем. Настоящая установка проверяется только после согласованной публикации
  валидного релиза и явного подтверждения пользователя.
